# 장면 키워드

4단계의 절차와 점검표다. 키워드가 서면 콘티는 거기서 풀려 나온다. 그래서 이 단계는 서두르지 않고, 사용자가 키워드 목록만 읽고도 영상이 그려진다고 할 때까지 고친다.

## 1. 재료

- 2단계 「요구」: 목적, 대상, 남길 한 줄, 형식.
- 3단계 카피 조사: 유형별 비율, 닳은 표현, 빈자리, 효과가 있던 카피의 결(길이·말투·구체성).
- 제품 사실: 기능, 화면, 확인된 숫자.

## 2. 서사 틀 고르기

영상 종류에 맞는 틀 하나를 고르고, 왜 그 틀인지 한 줄로 적는다. 틀은 출발점이다. 장면을 더하거나 합쳐도 되지만 흐름이 끊기면 안 된다.

| 영상 | 기본 흐름 |
|---|---|
| 제품 소개·홍보 | 붙잡기(첫 장면) → 공감(문제는 한 번만) → 다리(부정에서 긍정으로 넘어가는 장면) → 해결(기능 장면들) → 증거 → 행동·끝 문구 |
| 숏폼 | 붙잡기(1~2초) → 핵심 하나 보여 주기 → 결과 → 행동. 기능은 하나만 |
| 스토어 미리보기 | 정체(무엇인가) → 기능 묶음마다 제목 → 시연 → 결과 → 끝 문구 |
| 사용법 | 목적(이걸 하면 무엇이 되나) → 단계(제목 → 작동 → 설명) → 결과 |
| 이야기형(사례·전환기) | 계기 → 확장 → 일하는 장면들 → 원칙 → 맺음 |

## 3. 장면마다 적을 것

| 칸 | 뜻 |
|---|---|
| 장면 | 번호와 짧은 이름 |
| 핵심 키워드 | 그 장면이 시청자 머리에 남길 말 하나. 짧은 낱말이나 구 |
| 테마 한 문장 | 그 장면이 하려는 말 |
| 시청자 질문 | 이 장면이 답하는, 그 순간 시청자가 품은 질문 하나 |
| 감정 | 이 장면에서 시청자가 느낄 것(공감, 놀람, 안심 등) |
| 근거 | 카피 조사의 빈자리, 확인한 사실·화면 |

- 한 장면에 키워드는 하나다. 둘이 다투면 장면을 나눈다.
- 키워드는 3단계에서 고른 빈자리와 2단계 메시지가 겹치는 곳에서 뽑는다. 효과가 있던 카피의 결에 맞춰 다듬는다. 남의 카피를 옮기지 않는다.

## 4. 서사 점검

키워드 표를 다 쓰면 하나씩이 아니라 전체로 본다.

- **키워드만 이어 읽는다.** 키워드 줄만 소리 내어 읽었을 때 이야기가 되는가. 안 되면 빠진 장면이나 순서가 틀린 장면이 있다.
- **질문이 질문을 낳는가.** 각 장면의 답이 다음 장면의 질문을 자연스럽게 만드는가. 앞 장면에서 나오지 않은 질문에 답하는 장면은 순서가 틀렸거나 필요 없다.
- **감정 흐름**: 정한 흐름(예: 공감 → 신뢰 → 납득 → 안심 → 행동)을 따르는가. 문제·불편은 한 번만 짚는다. 해결을 보여 준 뒤 불편을 다시 꺼내면 잔소리가 된다.
- **붙잡기**: 첫 장면만 보고도 계속 볼 이유가 생기는가. 숏폼은 첫 1~2초, 일반 영상은 첫 5초.
- **끝**: 마지막 장면이 2단계의 "남길 한 줄"과 같은 말을 하는가. 시청자가 할 행동이 분명한가.
- **빠짐**: 2단계 목적에 필요한 장면이 다 있는가. 목적에 기여하지 않는 장면은 빼자고 제안한다.

## 5. 카피라이터 점검

키워드와 테마 문장마다 본다.

- **그림이 그려지는가.** 화면으로 보여 줄 수 있는 말인가. "효율", "혁신"처럼 그림이 없는 말이면 그 말이 가리키는 장면으로 바꾼다.
- **우리만 쓸 수 있는가.** 경쟁사가 이름만 바꿔 그대로 쓸 수 있으면 약하다. 제품의 동사·이름·재료에서 찾는다.
- **시청자의 말인가.** 만든 쪽의 기능 이름이 아니라 시청자가 그 상황에서 쓰는 말인가.
- **덜 해도 되는 일을 말하는가.** 시청자가 이제 하지 않아도 되는 일, 제품이 대신하는 일을 쉬운 말로 말하는가.
- **하나만 말하는가.** 한 키워드에 생각 하나.
- **닳지 않았는가.** 3단계에서 찾은 닳은 표현과 겹치지 않는가.
- **AI 틀이 아닌가.** "A가 아니라 B" 대구, 명사만 늘어놓은 조각, "경험·가치·솔루션·여정" 같은 추상어, 동사 세 개 나열을 쓰지 않는다. 표를 im-not-ai `humanize-scan`으로 재어 확인한다.

## 6. 사용자와 확정

- 표와 "키워드 줄만 이어 읽은 문장"을 함께 보여 준다.
- 점검에서 걸린 곳은 고친 안 2~3개를 이유와 함께 내고 고르게 한다.
- 사용자가 확정하면 기획 문서 「장면 키워드」에 적는다. 이후 콘티·대본·디자인은 이 표를 벗어나지 않는다. 바꿔야 하면 이 표를 먼저 고치고 다시 확정받는다.

## 예 (음성 입력 앱의 스토어 영상)

- 서사 틀: 정체 → 기능 묶음 → 끝 문구.
- 기능 장면은 "제목 → 미니어처 → 키 누름 → 말 → 끝냄 → 다듬음 → 형광펜 → 설명 두 줄"을 고정 순서로 되풀이했다. 고정 순서가 있으면 시청자는 두 번째 기능부터 어디를 볼지 안다.
- 사용법 24편 1판은 장면마다 근거(코드 위치)를 적지 않고 만들어, 실제 앱과 다른 내용이 나와 전부 다시 만들었다. 근거 칸을 두는 이유다.
