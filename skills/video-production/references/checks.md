# 점검

10단계에서 소리 → 화면 → 내용 → 문구 순서로 본다. 각 항목을 통과·실패·확인 못 함으로 적고, 실패는 시각·근거·고칠 방법을 붙인다. 여러 편이면 묶음 단위로 보고하고, 사용자가 고른 것을 모아 고친 뒤 처음부터 다시 본다.

## 준비

- 장면표: 일정 간격 캡처를 한 장에 모은 것.

```bash
ffmpeg -v error -i out/<이름>.mp4 -vf "fps=1/1.5,scale=480:-1,tile=6x6" -frames:v 1 out/<이름>-sheet.jpg
```

- 장면표는 표본이다. 빠른 동작, 전환, 장면 접합부는 그 시각의 프레임을 따로 뽑아 본다(`-ss <초> -frames:v 1`).
- 정상 속도 재생 확인은 사용자에게 요청한다. 정지 그림이 맞아도 움직임·싱크는 재생해야 보인다.

## 소리

소리는 그림으로 판정하지 않는다. 측정할 것은 에이전트가 재고, 귀로만 알 수 있는 것은 사용자에게 들어 달라고 요청한다.

- 줄마다 말끝이 잘리지 않았는가(측정: 각 음성 파일 마지막 30ms가 최고점보다 −40dB 아래).
- 한 편 안에서 같은 목소리가 같은 음색인가(사용자 청취).
- 장면 전환에 잘리거나 겹친 소리가 없는가(측정: 제작 스크립트가 만든 소리 배치 목록(클립마다 시작·길이)을 장면 경계 시각과 대조해, 경계를 넘거나 목소리끼리 겹치는 클립을 찾는다).
- 목소리 배정·말 속도가 확정한 대로인가.
- 내레이션과 자막·화면 글이 같은 말인가.
- 효과음이 정한 때에만 나는가.
- 음악이 말소리를 덮지 않는가, 끝에서 자연스럽게 줄어드는가(사용자 청취).
- 최종 음량 −16 LUFS(`encode.py` 출력 또는 `ffmpeg -i <파일> -af ebur128 -f null -`).

## 화면

- 창·화면 비율이 실제와 같은가(세로 창을 가로로 그리지 않았는가).
- 배치: 한 편 안에서 창 자리가 같은가, 글과 창이 겹치지 않는가, 숏폼은 플랫폼 단추·설명 글에 가리지 않는가.
- 실제 표시 크기에서 글자가 읽히는가, 읽을 시간이 있는가.
- 형광펜·강조가 바뀐 곳에만 정확히 칠해졌는가.
- 전환: 정보를 싣지 않는가, 같은 전환이 연달아 나오지 않는가, 장면 뒤로 숨지 않는가.
- 디자인 컨셉의 참고 고정과 "하지 않을 것"을 지켰는가.
- 화면 가장자리 띠, 깜박임, 잘림, 글자 깨짐이 없는가.

## 내용

- 앱 문구·단추 이름·동작·순서를 실제 화면이나 코드와 대조했는가(근거 `파일:줄`).
- 다른 플랫폼 모양(아이폰 상태 표시줄, 맥 창 단추)이 섞이지 않았는가.
- 사용자가 바꿀 수 있는 값을 고정된 것처럼 보이지 않는가.
- 숫자·주장이 확인된 것뿐인가.
- 개인 자료·고객 정보·다른 회사 상표가 화면에 없는가.

## 문구

- im-not-ai 최신판 `humanize-scan`으로 화면 글·자막·내레이션을 다시 잰다. 걸린 것은 `humanize-korean`으로 고친다. 내레이션의 쉼표는 목소리 쉼으로 둘 수 있다.
- `user-copy`로 처음 보는 사람 입장에서 읽는다: 모르는 말을 풀었는가, 보이는 것을 다시 말하지 않는가, 누가 무엇을 하는지 보이는가.
- 키워드 표와 같은 말을 하는가(콘티가 키워드에서 벗어나지 않았는가).
