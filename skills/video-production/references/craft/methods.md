# 모션 그래픽 제작 방법서

존코바 공개 제작 설명을 바탕으로 정리한 실무 방법과, HyperFrames·Claude Code 영상에서 추출한 장면 단위 제작 방식.

## 이 문서의 범위

- 조사일: 2026-10-20. JohnKOBA Design 정본 채널: https://www.youtube.com/channel/UCYpD5IVQK9BjA2qtupHFExA
- 공개 목록: 일반 영상 309편, 쇼츠 86편. 목록 확인은 내용 검토와 다르다.
- 1차 유효 발화 자막 55개에서 **43개 영상·109개 시간 구간 근거**를 추렸다. 후속 공개 페이지 추출 76개를 본문으로 다시 판정해 **71개 영상을 추가 채택**하고 4개를 제외, 1개를 채팅 오추출로 보류했다. 누적 채택은 **114개 영상**이다. 수집·검토 수는 독립 기법의 개수가 아니며 같은 설명은 제작 절차로 통합했다.
- 시간 구간이 있는 1차 근거와 시각 없는 후속 전사·번역 근거를 구분한다. 후속 자료는 자막 완전성·원 영상 정합성을 독립 검증하지 않았다. 현재 목록은 제작 관련 115개(채택 114개·채팅 보류 1개), 설명 확인 82개, 제외 198개다. 채널 전체 내용 검토 완료는 아니다.
- 기준은 모션 제작과의 직접적인 연결이다. 일반 디자인·기기·진로 영상은 직접 연결되는 구체 설명이 없으면 제외한다. 한글·영문 제목과 자막 모두 판단 자료이며, 언어 때문에 제외하지 않는다.
- 추가 영상: Science Based AI의 https://www.youtube.com/watch?v=y4YupFxhAog . 제작자 설명·챕터로 확인한 내용만 `hyperframes-shot-workflow.md`에 따로 정리했다. 자막·실행 검증은 하지 못했다.
- 이 문서에서 **원본 설명**은 출연자의 설명을 자막에서 확인했다는 뜻이다. 도구 성능·효과의 우수성이나 실습 성공을 검증했다는 뜻은 아니다. **실무 적용**은 여러 설명을 연결한 이 스킬의 제안이다.

## 1. 완성도보다 먼저, 무엇을 전달할지 정한다

### 이런 문제에 사용한다

구·액체·멋진 전환은 많은데 무엇을 소개하는지 기억나지 않는 영상. 개별 컷은 예쁘지만 전체가 이어지지 않는 영상.

### 원본 설명

존코바는 AI 보이스를 메인 키워드로 두고 음파·웨이브·음표·악기 같은 연관어를 확장한 뒤, 시각화할 요소를 골라 레퍼런스→콘셉트 스케치→키비주얼로 발전시킨다. 제품의 효용을 보여줄 때는 불편한 이전 상태와 제품이 바꾼 상태를 대비하는 피드백도 제시한다.

근거: [제품 키워드와 스케치](https://www.youtube.com/watch?v=6p7k4iMKWlE&t=279s), [제품 개입 전후의 서사](https://www.youtube.com/watch?v=NqT4dMON34g&t=779s).

### 실무 적용

1. 시청자가 보고 나서 알아야 할 내용을 한 문장으로 적는다.
2. 그 문장의 핵심 단어를 동작·형태·관계로 바꾼다. 예를 들어 ‘음성 입력’은 파형 자체가 아니라 말하기→문자 생성→사용이라는 변화로 보여줄 수 있다.
3. 첫 장면과 마지막 장면을 먼저 스케치한다. 그 사이에 필요한 사건만 배치한다.
4. 각 장면에 ‘이 컷이 있어야 하는 이유’를 적는다. 역할이 중복되면 합치고, 움직이지 않아도 설명되는 장면은 그대로 둔다.
5. 확정되지 않은 제품 효능·수치를 연출로 사실처럼 만들지 않는다.

**판정:** 처음 보는 사람이 영상이 소개하는 대상과 변화를 설명할 수 있는가? 못한다면 효과가 아니라 메시지·장면 순서를 고친다.

## 2. 레퍼런스는 모아서 흉내 내는 것이 아니라, 역할을 분해한다

### 원본 설명

레퍼런스를 수집하고 구도·포즈·주변 물체·문자를 임시로 조립한 뒤, 자기 형태로 다시 스케치하고 채색·움직임으로 발전시키는 과정을 보여준다. AI 작업에서는 기준 한 장인 앵커 이미지와 캐릭터 설정도·장면별 스타일 프레임을 먼저 마련한다.

근거: [수집·분해·조립](https://www.youtube.com/watch?v=0hqu_lA8Og0&t=70s), [앵커 이미지와 스타일 프레임](https://www.youtube.com/watch?v=CjsEbRGbn5I&t=130s), [보드와 캐릭터 준비](https://www.youtube.com/watch?v=y7eVSK2ODVE&t=143s).

### 작업 순서

- 레퍼런스별로 참고할 대상을 적는다: 구도, 색 비중, 형태, 리듬, 카메라, 연결 방식.
- 작품의 고유한 구성·캐릭터를 그대로 결과물에 옮기지 않는다. 학습용 임시 조립과 실제 납품 자산을 분리한다.
- 장면마다 다시 색을 찍지 말고 공통 팔레트를 재사용한다.
- 생성 이미지의 스타일 프레임을 나란히 놓고 인물·제품·배경·빛이 일관되는지 비교한다.

**판정:** 참고한 원리를 설명할 수 있고, 최종 자산의 이용 권한도 확인할 수 있는가? 여러 작품을 섞거나 다시 그렸다는 이유만으로 권리 문제가 해결된다고 보지 않는다.

## 3. 정지 프레임과 애니메틱을 서로 다른 검사로 사용한다

### 먼저 준비할 것

핵심 메시지, 러프 장면표, 대략의 스타일 방향, 임시 도형과 글자. 최종 캐릭터 리깅·질감·조명까지 완성한 상태는 필요하지 않다.

### 원본 설명

정지 프레임에서 형태·레이아웃·컬러·묘사가 읽혀야 하고, 움직임을 늘려 그래픽의 문제를 가리면 안 된다고 설명한다. 한편 실제 제작에서는 콘티로 단순한 1차 애니메틱을 만들고, 일부 디자인과 더 조밀한 움직임을 넣은 2차 애니메틱으로 발전시킨다.

근거: [그래픽을 먼저 읽히게 만들기](https://www.youtube.com/watch?v=k9LFDbKr8ro&t=42s), [1차·2차 애니메틱](https://www.youtube.com/watch?v=pUkdpljy240&t=44s), [프록시로 동선 잡기](https://www.youtube.com/watch?v=MN0_L34pFG8&t=273s).

### 실무 적용

1. 대표 프레임으로 주인공·읽는 순서·색과 형태를 확인한다.
2. 간단한 도형으로 등장→이동→충돌→전환을 시간축에 올린다.
3. 정상 속도로 재생해 사건의 흐름과 읽기 시간을 본다.
4. 흐름이 통과하면 디자인을 일부 교체하고 가감속·반응·연결을 다듬는다.
5. 마지막에 캐릭터의 세부 부위·질감·조명·음향을 올린다.

‘그래픽 먼저’는 전체 아트웍을 끝내고 나서야 움직임을 시험하라는 뜻이 아니다. **정지 화면의 정보 설계와 시간축의 흐름을 각각 일찍 확인하라는 두 검사**다.

**판정:** 임시 도형만으로도 사건이 이해되는가? 최종 색을 빼도 핵심이 읽히는가? 둘 중 하나가 실패하면 장식을 늘리지 않는다.

## 4. 커서 클릭 예제로 배우는 움직임의 8가지 관점

원본은 버튼·커서를 발전시키는 순서로 설명한다. 아래는 모든 영상에 전부 넣을 필수 효과가 아니라 **문제에 맞게 선택할 개선 관점**이다.

근거: [8단계 루틴](https://www.youtube.com/watch?v=STDMpreUyI4&t=33s). 자막 외에 이 영상의 표본 프레임에서 버튼·커서·파편 표현을 확인했다. 전체 재생·직접 실습 검증은 아니다.

| 관점 | 원본의 예제 | 작업할 때 확인할 것 |
|---|---|---|
| 가감속 | F9 또는 이지 인·아웃으로 출발과 정지를 부드럽게 함 | 물체의 무게와 브랜드 톤에 맞는 속도 변화인가? 기본 이징만 반복하지 않는다. |
| 이동 경로 | 곡선으로 커서가 날아 들어옴 | 목표로 가는 동선이 명료한가? 직선도 의도에 맞으면 유지한다. |
| 스쿼시 앤 스트레치 | 빠른 커서는 얇게, 클릭된 버튼은 눌렸다 복귀 | 재질·힘이 읽히는가? 정확한 글자·로고가 망가지지 않는가? |
| 준비 동작 | 클릭 전에 반대 방향으로 살짝 물러남 | 다음 행동을 기대하게 하는가? 불필요하게 기다리게 하지는 않는가? |
| 잔여 동작 | 클릭 후 힘을 받아 커서가 살짝 뒤로 밀림 | 뚝 끊기지 않고 끝났다는 느낌도 있는가? |
| 2차 동작 | 클릭에 파동·작은 조각이 반응 | 주동작을 설명하는가, 주인공보다 튀는 장식인가? |
| 오프셋 | 파동·파편의 시작·도착·소멸을 조금씩 다르게 함 | 원인과 결과가 연결되는가? 무작위 지연이 아닌가? |
| 과장 | 확대·반짝임·속도 변화로 클릭을 강조 | 강조가 필요한 곳인가? 가독성·접근성·브랜드 톤을 해치지 않는가? |

### 헷갈리기 쉬운 구분

- **오버슛:** 목표 위치나 각도를 잠깐 지나갔다 돌아온다.
- **오프셋:** 연결된 요소가 시간차를 두고 움직인다.
- **2차 동작:** 주동작을 보강하는 반응을 추가한다.
- **바운스:** 접촉과 탄성에 따른 튕김이다. 물체마다 무게·재질을 다르게 표현한다.
- **아이들링:** 주 액션이 없을 때의 미세한 살아 있음이다. 모든 정보 화면을 계속 흔드는 효과가 아니다.

근거: [수저·액체·구슬의 실제 작업 분해](https://www.youtube.com/watch?v=pUkdpljy240&t=135s), [아이들링과 물성](https://www.youtube.com/watch?v=k9LFDbKr8ro&t=251s).

**판정:** 준비→본 동작→반응→정착을 읽을 수 있는가? 효과를 끄면 원래 동작이 엉성한 상태라면 주동작부터 고친다.

## 5. 음악의 박자와 정보의 호흡은 따로 설계하고 연결한다

### 원본 설명

음악 비트에 마커를 찍고 풀샷·클로즈업·타임 리매핑을 조합한다. 제품을 보여줄 때는 느리게 하고 이동 구간은 빠르게 만드는 대비, 음악이 비는 순간 움직임도 비우는 사례가 있다. 피드백에서는 호흡이 빠르다는 것이 반드시 동작 속도가 빠르다는 뜻이 아니라 풀어 주는 공간이 없다는 뜻이라고 구분한다.

근거: [음악 마커와 타임 리매핑](https://www.youtube.com/watch?v=JgCHnStoiB8&t=122s), [속도 대비](https://www.youtube.com/watch?v=fA5VToI-hv4&t=96s), [호흡과 쉼](https://www.youtube.com/watch?v=R9edOvfC8S0&t=570s).

### 작업 순서

1. 음원의 실제 비트·마디·강약·쉼을 확인한다.
2. 장면별로 ‘이동을 느낄 시간’과 ‘대상을 관찰할 시간’을 나눈다.
3. 중요한 착지·타격·전환을 음악의 지점과 연결한다.
4. 정보가 읽히지 않으면 모든 것을 느리게 하기보다 문장을 나누거나 컷의 밀도를 줄인다.
5. 긴 준비 동작 때문에 핵심이 늦게 나오면 앞부분을 줄인다.

### 제품 소개 영상 기준 (이 스킬 작성자)

이 항목은 존코바의 발언이 아니라 이 스킬 작성자의 기존 제작 방향이다.

- 기능을 설명하는 동안 배경은 안정시키고 설명 대상만 움직인다.
- 기능 사이 전환은 시각적 연결로 사용하며 정보를 동시에 읽히게 하지 않는다.
- 다음 기능 제목은 전환이 끝난 뒤 보여준다.
- 빠르되 박자·마디·쉼이 있어야 한다. ‘빠른 영상’과 ‘리듬 없는 영상’은 다르다.

**판정:** 실제 시청 크기·정상 속도에서 처음 보는 사람이 읽을 수 있는가? 전환만 보다가 기능 설명을 놓치지 않는가?

## 6. 샷의 역할을 정하면 같은 소재도 달라진다

전체 공간은 넓은 샷, 행동·타격·디테일은 가까운 샷처럼 **보여주는 이유**를 정한다. 전경·중경·원경을 분리하면 평면 장면에도 깊이를 만들 수 있다. 로우·하이·더치·탑다운·아이소메트릭은 감정과 정보에 맞춰 선택하며 같은 시점을 반복하지 않기 위한 장식으로 쓰지 않는다.

근거: [구도와 샷의 역할](https://www.youtube.com/watch?v=Z4qfIunxkNE&t=27s), [샷과 음악의 연결](https://www.youtube.com/watch?v=o87ECfdxQ48&t=252s).

### 움직일 아트웍의 준비

모션 아트웍의 앞뒤 배치·면의 두께·그라데이션·접촉 그림자와 림라이트는 깊이와 접지를 돕는다. 단, 이런 준비 과정을 카메라 애니메이션의 완전한 구현법으로 바꾸어 설명하지 않는다.

근거: [모션 아트웍의 깊이·양감](https://www.youtube.com/watch?v=pono-IIBAgg&t=161s). 이 자료는 확보된 영어 자막으로 확인했다.

**판정:** 정지 화면에서 주목점과 공간이 읽히고, 움직일 때도 앞뒤 관계가 유지되는가? 정확한 카메라 각도·렌즈·속도비가 원본에 없으면 추측하지 않는다.

## 7. 장면 연결은 형태·방향·가림 중 무엇을 이어 줄지 고른다

### 재사용할 연결 방식

| 연결할 것 | 방법 | 검수 기준 |
|---|---|---|
| 같은 형태·심볼 | 그래픽 매치컷: 디자인은 바뀌어도 공통 형태를 유지 | 심볼이 같은 것으로 읽히는가? |

## 8. 페이크 3D는 필요한 수준의 면과 두께만 만든다

근거: [세 가지 페이크 3D 방법](https://www.youtube.com/watch?v=rQjMCC3klc8&t=82s).

### A. 스케일과 패스로 측면 만들기

정면·반측면의 형태를 관찰한다 → 정면 도형을 납작하게 줄인다 → 펜툴로 측면을 그린다 → 돌아오는 각도에 맞춰 패스를 움직인다 → 면별 색을 구분한다.

**적합:** 단순한 형태의 짧은 회전. **검수:** 앞·옆면이 벌어지거나 측면이 순간적으로 튀지 않는가?

### B. 리피터로 선을 면처럼 만들기

라인 애니메이션을 만든다 → 촘촘한 반복으로 면·두께가 읽히게 한다 → 그라데이션으로 양감을 보완한다.

**적합:** 종이·띠·선 기반 표현. **검수:** 최종 출력에서 반복 간격이 구멍·깜빡임처럼 드러나지 않는가?

### C. AE 3D와 RGB 채널 매트 조합

레이어를 3D로 켜고 카메라를 둔다 → 소스 형태를 Red, 복제 형태를 Green으로 나누고 조금 이동한다 → 솔리드에 Gradient Ramp와 Set Matte를 적용한다 → RGB 소스의 Red 채널로 한 면을 제한한다 → 솔리드를 복제해 Green 채널에 다른 그라데이션을 넣는다.

**적합:** 양면이 다른 종이·띠 표현. **검수:** 임시 색으로 채널 분리가 맞는지 확인한 뒤 그라데이션을 넣는다. 이는 실제 3D와 가짜 양감의 혼합이다. ‘3D를 전혀 쓰지 않는다’고 부르지 않는다.

정확한 패스 좌표·반복 개수·매트 옵션·위치 오프셋은 공개 자막만으로 확인할 수 없다. 실행 환경에서 작은 시험으로 정해야 한다. 복잡한 사물·큰 회전에는 실제 3D가 더 적합할 수 있다.

### 실제 피드백으로 보는 접지와 물성

- 차량: 무채색으로 유리창→몸통→두께 있는 바퀴→라이트를 만들고, 도로의 투시와 차량 경로·덜컹거림·그림자를 맞춘 다음 브랜드색을 넣는다. 드리프트의 인상이 제품 메시지와 맞는지도 본다. [차량 예제](https://www.youtube.com/watch?v=_rarY0PC-80&t=345s)
- 구슬: 구의 회전과 고정 광원 아래 하이라이트를 분리하고, 바닥 그림자·반사광을 맞춘다. 표면 무늬처럼 하이라이트까지 함께 돌리지 않는다. [구슬 예제](https://www.youtube.com/watch?v=4vB2Zv8c4ow&t=164s)

## 9. AI 제작은 기준 이미지·명확한 동작·선별 편집의 조합이다

### 이미지에서 영상으로

1. 캐릭터·제품의 기준 이미지와 장면별 스타일 프레임을 확정한다.
2. ‘자연스럽게 움직여’ 대신 준비→본 동작→잔여 동작, 방향·목표·카메라를 적는다.
3. 결과에서 꼭 남아야 할 물체·소품·문자·형태가 유지되는지 본다.
4. 맞는 컷을 선별해 연결하고 정확한 정보·텍스트·소리·타이밍은 후반 편집한다.
5. 선택한 컷을 고해상도화하더라도 형태·문자·일관성을 다시 확인한다.

근거: [동작을 구체화하는 프롬프트](https://www.youtube.com/watch?v=CjsEbRGbn5I&t=306s), [클립의 동작·방향 검수](https://www.youtube.com/watch?v=y7eVSK2ODVE&t=325s), [직접 후반 작업](https://www.youtube.com/watch?v=8K72eoxW1-s&t=426s).

생성 후보의 수·해상도·길이는 사례이지 고정 기본값이 아니다. 무한 재시도를 하지 말고, 승인된 비용과 실제 성공·실패 원인을 보고 수정하거나 편집·수작업 경로로 옮긴다. 구독·API·유료 서비스의 승인 범위를 바꾸지 않는다.

### AI 키네틱 타이포

레퍼런스와 확정된 자기 카피로 시작하고, 컷의 호흡·타입 크기·색·라인·점 등 **무엇을 바꿀지 구체적으로 요청**한다. 수정 전후 버전을 보존하고, 한글은 원문과 대조한다. 중요한 글자·로고·정확한 타이밍은 별도 레이어의 편집 가능한 요소로 보호한다.

근거: [AI 타입 모션 시험과 한계](https://www.youtube.com/watch?v=5-r5meceIGg&t=56s).

### 이미지에서 3D 자산으로

이미지·멀티뷰 준비→3D 생성→뒷면·재질·노멀 검사→필요시 리깅과 동작 미리보기→메시 경량화·파트 분리→호환 형식으로 내보내기→편집기에서 재질·등장·회전·카메라 구성.

근거: [이미지 기반 3D와 AE 활용](https://www.youtube.com/watch?v=VGM5HYi6Aik&t=52s).

생성된 3D가 상품의 실제 형태라는 보장은 없다. 폴리곤 목표·포맷 지원·반사 속성은 사용 중인 도구와 자산에 맞게 확인한다.

## 10. 코드·에이전트 기반으로는 짧은 장면을 독립적으로 제작한다

추가 출처는 존코바가 아닌 Science Based AI의 영상이다. **제작자 상세 설명·챕터 기반**이며 전체 자막은 확보하지 못했다. 상세 절차·확인 한계는 [HyperFrames 장면 제작 방법](hyperframes-shot-workflow.md)에 있다.

1. 레퍼런스 이미지와 실제 데이터를 구분해 준비한다.
2. 대본에서 시각화하면 이해가 쉬워지는 지점을 고른다.
3. 장면마다 공통 스타일·카피·카메라·시작과 끝·출력 조건을 전달한다.
4. 서로 독립된 클립만 필요에 따라 병렬 제작한다.
5. 플랫폼 UI 안전 영역·정확한 수치·로고를 확인하며 편집자처럼 수정한다.
6. 최종 길이·음악·자막은 후반 편집에서 맞춘다.

[원본 01:07 데이터 차트](https://www.youtube.com/watch?v=y4YupFxhAog&t=67s), [05:39 대본의 시각화 지점](https://www.youtube.com/watch?v=y4YupFxhAog&t=339s), [10:50 여섯 가지 개선 요령](https://www.youtube.com/watch?v=y4YupFxhAog&t=650s).

초기 애니메틱의 예상 박자 설계와 후반 편집의 최종 싱크는 다르다. 생성된 클립 때문에 정보 읽는 시간과 음악 박자를 억지로 바꾸지 않도록 편집 여유를 둔다. HyperFrames 설치나 기존 렌더 경로 교체를 의무로 하지 않는다.

## 11. 마감은 ‘효과 추가’가 아니라 결함을 없애는 단계다

### 제작 중 확인

- 주연이 읽히기 전에 배경 세부에 시간을 쓰지 않는다.
- 키샷·전환 시험이 통과한 뒤 전체 컷에 스타일을 확장한다.
- 샷 크기가 바뀔 때 선 굵기·질감·색이 튀지 않는지 연속 재생한다.
- 물체의 앞뒤 가림, 잘림, 접촉 그림자, 순간 소실을 확인한다.
- 모션 블러·먼지·스플래시·반짝임으로 기본 동작의 문제를 덮지 않는다.

근거: [과한 효과와 물리·부위 분리](https://www.youtube.com/watch?v=JV8tliiWc40&t=295s), [키샷과 재질 시험](https://www.youtube.com/watch?v=NqT4dMON34g&t=919s), [실기 작업 피드백](https://www.youtube.com/watch?v=Z-Pw8umTJsU&t=524s).

### 최종 파일 확인 — 이 스킬의 납품 기준

1. 정상 속도로 처음부터 끝까지 재생한다. 일부 장면만 완성된 상태는 완료가 아니다.
2. 실제 시청 크기에서 글자·기능·주인공이 읽히는지 본다.
3. 접합부·빠른 운동·충돌은 프레임 단위로 확인한다.
4. 차트 수치·브랜드색·문구·로고를 승인 자료와 대조한다.
5. 밴딩·얼룩·깜빡임·잘림·오디오 싱크·안전 영역을 검사한다.
6. 최종 인코딩 파일의 길이·해상도·프레임레이트·코덱을 확인한다. 편집기 미리보기만으로 대신하지 않는다.
7. 원본 소스와 실제 출력 파일·확인 결과·미확인 사항을 전달한다.

도구가 없거나 필요한 정보·권한·자료가 없으면 정확한 차단 사유와 가능한 산출물을 남긴다. 미실행·미검수 결과를 렌더 완료나 납품 완료로 표시하지 않는다.

## 12. 후속 자료에서 정제한 실행 레시피

아래는 반복 예제를 목적별로 합친 작업 순서다. AE에서 설명된 방법을 Pillow로 옮기는 부분은 **이 스킬의 구현 제안**이며 출처의 코드가 아니다. 도구·프리셋이 없어도 동작의 원리와 검수 조건을 유지한다. 정확한 원문 근거는 `evidence.json`의 해당 `page_reviews` 항목을 확인한다.

### A. 움직일 자산을 분리한다

- **사용:** 그림 한 장을 캐릭터·배경·소품으로 나눠 움직여야 할 때.
- **순서:** 실제로 다른 동작을 할 부위만 독립 레이어/이미지로 준비 → 회전 중심과 가림 순서 지정 → 가장 큰 동작으로 관절·잘림 시험 → 본 동작 후 표정·머리카락·소품 반응 추가.
- **실행 연결:** `scene.py` 초기화에서 알파 이미지를 로드하고 `frame(t)`에서 합성한다. 팔·날개·머리 등의 변환 중심을 구분한다. PSD 레이어를 그대로 읽는 기능이 있다고 가정하지 말고 필요한 투명 자산으로 내보내거나 기존 AE 경로를 사용한다.
- **검수:** 회전할 때 빈틈·잘린 끝·잘못된 앞뒤 가림이 없는가? 원본이 한 장이고 부위를 복원할 근거가 없으면 정교한 리깅이 완료됐다고 하지 않는다.
- **근거:** [레이어 보존·캐릭터 부위](https://www.youtube.com/watch?v=vo7MRPRme3M), [움직일 그림 준비](https://www.youtube.com/watch?v=DgDLcJ31eow), [PSD와 순차 모션](https://www.youtube.com/watch?v=pXlcrsOsShA).

### B. 속도 그래프를 궤적과 구분한다

- **사용:** 시작과 정지가 뻣뻣하거나 튕김에 무게가 없을 때.
- **순서:** 시작·목표 위치와 시간 지정 → 위치 경로를 먼저 정함 → 시간에 따른 이동 비율을 이징 함수로 조절 → 바운스는 공중 정점과 충돌 지점의 속도 대비를 만듦 → 주위 요소의 반응을 접촉 뒤 배치.
- **실행 연결:** `u=(t-start)/duration`을 0~1로 제한한 뒤 위치를 보간한다. 오버슛은 목표를 넘었다 돌아오는 별도 곡선으로 설계하고 강도·감쇠를 대상의 성격에 맞춘다. 전 구간에 같은 F9·고정 벨로시티 값을 복사하지 않는다.
- **검수:** 경로를 바꿔야 할 문제를 이징만으로 가리지 않는가? 바닥을 뚫거나 반응이 접촉 전에 시작하지 않는가?
- **근거:** [축·그래프·바운스](https://www.youtube.com/watch?v=XKGbeZVy3dU), [모션 원리 실습](https://www.youtube.com/watch?v=wwMCJbCgb3o).

### C. 시간차는 물체 사이의 힘을 전달한다

- **사용:** 문자·여러 요소가 통째로 움직이거나 머리카락·팔이 기계적으로 따라올 때.
- **순서:** 주동작을 먼저 완성 → 따라갈 요소의 순서와 원인 지정 → 요소마다 시작 시각을 지연 → 끝의 정착·복귀도 확인. 헤드→몸통→팔 같은 관계는 해당 행동에 맞는 경우에만 사용한다.
- **실행 연결:** 요소별로 `local_t=t-start-delay`를 계산하고 같은 동작 함수에 전달한다. 프레임 단위 레퍼런스는 현재 FPS의 초 단위로 해석하며 예제의 2~5프레임·3프레임 지연을 기본값으로 굳히지 않는다.
- **검수:** 누적 지연 때문에 끝 요소가 화면 밖에 남거나 정보가 늦게 읽히지 않는가? 불필요한 아이들링은 끈다.
- **근거:** [부위별 후행](https://www.youtube.com/watch?v=_nCGdtBEDxc), [퍼펫 핀 지연](https://www.youtube.com/watch?v=6Glm0OvNXFI), [오브젝트 오프셋](https://www.youtube.com/watch?v=hxe2uADcsVk).

### D. 타이포는 읽는 단위와 움직이는 단위를 나눈다

- **사용:** 로고·문구가 순차 등장하거나 글자 안에 영상·이미지가 보여야 할 때.
- **순서:** 확정 카피·폰트·줄바꿈으로 정지 배치 → 단어/줄/글자 중 의미가 유지되는 단위 선택 → 등장·머무름·퇴장 구간 지정 → 필요한 부분만 마스크로 공개 → 다음 컷의 색·형태로 연결.
- **실행 연결:** Pillow의 실제 글자 폭으로 위치를 계산하고 알파 마스크·크롭·합성으로 리빌을 만든다. 한글 자소 분할·과도한 늘임은 요청과 가독성에 맞는 경우만 사용한다. Flex·EasyFlow는 영상의 선택 도구이지 설치 전제나 복원된 API가 아니다.
- **검수:** 철자·조사·기호·줄바꿈을 원문과 대조하고 전체 문장을 읽을 안정 구간을 남긴다. 빠른 플래시·흔들림은 기본 장식으로 복사하지 않는다.
- **근거:** [타이포 리듬](https://www.youtube.com/watch?v=ZQ3hYvViUd4), [글자별 타이밍](https://www.youtube.com/watch?v=KjlHiudGO-Q), [마스크 리빌](https://www.youtube.com/watch?v=72IO6HWrT4M).

### E. 샷과 전환은 연결할 대상부터 고른다

- **사용:** 같은 크기의 화면만 반복되거나 두 장면이 끊겨 보일 때.
- **순서:** 넓은 샷은 공간, 가까운 샷은 행동·디테일이라는 역할 부여 → 다음 컷과 공유할 위치·속도·형태·가림 중 하나를 선택 → 접합부 시험 → 장면의 정보 체류 시간을 확보.
- **실행 연결:** 평면 구도 변화는 장면 레이어의 이동·스케일·크롭, 와이프는 마스크, 매치컷은 전후 상태 정렬로 구현한다. 2D 확대를 실제 3D 카메라로 표시하지 않는다. 모핑은 대응하는 형태가 있을 때만 직접 보간한다.
- **검수:** 시선이 순간 이동하거나 모핑 중 형태가 무너지는가? 공통 요소가 없으면 단순 컷·화면 유지도 선택한다.
- **근거:** [여섯 전환 원리](https://www.youtube.com/watch?v=Zz4O86pN5iU), [널 기반 샷 구성](https://www.youtube.com/watch?v=_EqE7C3fp_E), [사진 한 장의 샷 분해](https://www.youtube.com/watch?v=EWk8C6sDWoE).

### F. 손맛·잔상·입체감은 기본 동작 뒤에 추가한다

- **사용:** 동작은 맞지만 스타일의 밀도나 물성이 부족할 때.
- **순서:** 기본 동작을 정상 재생 → 의도에 맞으면 포즈 갱신 간격을 낮춰 스텝 느낌 구현 → 필요한 이동에만 잔상·미세 후행 추가 → 전경·중경·배경의 이동 차이와 그림자로 깊이 보완.
- **실행 연결:** 포즈만 낮은 빈도로 표본화하고 최종 영상 FPS는 납품 조건을 유지한다. 잔상은 이전 시각의 객체를 낮은 알파로 합성한다. 단순 2D 깊이와 실제 C4D 두께·광원은 다른 경로다.
- **검수:** 잔상·그림자가 본체보다 튀거나 글자를 지저분하게 만들지 않는가? 고정 광원의 하이라이트까지 물체에 붙어 회전하지 않는가?
- **근거:** [Posterize Time과 부위 분할](https://www.youtube.com/watch?v=Ns6OZD8KIgY), [반동·트레일](https://www.youtube.com/watch?v=nzrYHSrguw4), [AE 3D 제작](https://www.youtube.com/watch?v=lw1NvP3IVMs).

### G. 출력 형식은 배치할 곳에 맞춘다

- **사용:** 완성 영상, 투명 오버레이, Lottie 등 서로 다른 납품이 요구될 때.
- **순서:** 사용처의 코덱·알파·음향 요구 확인 → 실제 지원하는 출력 경로 선택 → 최종 파일을 대상에서 합성·재생해 확인.
- **실행 연결:** 이 스킬의 실행기는 일반 H.264 MP4를 만든다. 투명 배경·Lottie·AE 프로젝트가 필수면 해당 기능을 지원하는 기존 도구와 원본 제작 경로를 사용한다. 검은 배경 MP4를 투명 오버레이로 전달하지 않는다. Lottie는 매트·효과 지원을 실제 호환 표와 출력 결과로 확인한다.
- **근거:** [H.264와 알파 출력](https://www.youtube.com/watch?v=OuegvWTccXM), [투명 구독 버튼 합성](https://www.youtube.com/watch?v=yJYKOCdI2tA), [Lottie 기능 호환](https://www.youtube.com/watch?v=jAg9AfYL3tI).
