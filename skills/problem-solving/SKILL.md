# 문제해결

다른 일을 하기 전에 이 스킬 폴더의 `scripts/walk.py`를 인자 없이 실행하고, 출력된 안내를 따르세요.

## 처음 쓰기 전에 (사용자가 정할 것)

이 스킬에는 두 가지 방식이 있습니다.

- 직접 진행: 지금 쓰는 에이전트가 질문을 하나씩 스스로 묻고 답합니다. 모델이나 키를 따로 정하지 않아도 됩니다.
- 스크립트 진행: 지금까지의 대화를 모르는 새 조사 에이전트가 질문에 답하고, 판정 모델이 그 답을 가립니다. 처음 쓰기 전에 아래 설정이 필요합니다.

일을 해 온 에이전트는 원인을 이미 정해 두고 답을 거기에 맞추기 쉽습니다. 그래서 스크립트 방식은 조사를 맥락 없는 에이전트에게 맡기고, 답이 질문에 맞는지와 근거가 실제 도구 기록에 있는지는 다른 모델(Jev)이 가립니다. 조사 에이전트가 자기 답을 스스로 채점하지 않게 하려는 것입니다.

스크립트를 실행하면 맨 먼저 설정을 점검합니다. 빠진 것이 있으면 에이전트가 진행 방식을 고르게 하기 전에 무엇이 빠졌는지와 넣는 법을 알리고, 그동안은 직접 진행만 쓸 수 있습니다. 모델은 실행 전에 사용자가 정해 둬야 하며, 에이전트가 대신 고르지 않습니다. 쓰는 모델이 만든 사람과 같지 않아도 됩니다. 아래 기준에 맞는 모델을 고르세요.

### 1. 조사 에이전트 모델

조사 에이전트는 셸과 파일 도구로 서버·코드·기록을 직접 확인하면서 질문 하나에 답합니다. 질문 하나에 몇 분에서 십여 분이 걸립니다. 한 번 조사할 때 질문을 적어도 5번 하고(현상, 원인 2번 이상, 전체 흐름, 해결책), 원인 사슬이 길면 10번이 넘습니다.

- 수준: 도구를 쓰며 여러 단계를 끝까지 조사하는 에이전트 코딩에서 최상위급 모델을 고르세요. 약한 모델은 확인하지 않고 짐작으로 답하는 일이 잦습니다. 그러면 근거 판정에서 되물음을 받고, 두 번째에도 근거가 없으면 조사가 멈춥니다.
- 비용: 쓰는 토큰이 많으니 CLI 구독 요금제를 권합니다. API 종량제로 쓰면 한 번에 드는 비용이 커질 수 있습니다.
- 부르는 방식은 두 가지입니다. 쓰는 앱에 맞춰 하나만 정해도 됩니다.

| 실행 | 필요한 것 | 설정 이름 | 넣는 값 |
|---|---|---|---|
| `start claude` | Claude Code CLI(`claude`), 로그인됨 | `INVESTIGATOR_CLAUDE_MODEL` | `claude --model`에 넣는 이름. 예: `opus`(만든 사람이 쓰는 값), `sonnet` |
| `start codex` | Codex CLI(`codex`), 로그인됨 | `INVESTIGATOR_CODEX_MODEL` | `codex exec -m`에 넣는 이름. 그 계정에서 쓸 수 있는 최상위 추론 모델. 예: 만든 사람은 `gpt-6.1-sol` |

Claude Code에서 쓰면 `claude`, 그 밖의 앱(Codex 등)에서 쓰면 `codex`로 실행합니다. 두 CLI 말고 다른 모델로 조사하려면 `walk.py`의 `claude()`·`codex()`처럼 그 모델을 부르는 함수를 하나 더 만들어야 합니다. 그 함수는 실제 도구 실행 기록을 `observation`으로 남겨야 합니다. 판정 모델이 그 기록과 답을 맞춰 보기 때문입니다.

### 2. 판정 모델 Jev

[Jev](https://docs.typesafe.ai/introduction)는 TypeSafe의 판정 전용 모델입니다. 글을 쓰지 않고, 정해 둔 보기 가운데 하나(choice)나 어떤 문장이 참일 확률(noul)만 돌려줍니다. 빠르고 싸서, 질문마다 붙는 판정을 맡기기에 맞습니다. 2026-10 기준 가격은 100만 입력 토큰당 0.042달러이고, 출력은 받지 않습니다.

- 하는 일: 답마다 한 번 불러 두 가지를 함께 묻습니다.
  - 답이 질문에 맞는가: 현상만 적었는가, 더 앞선 원인을 댔는가(같은 말 반복인지, 원인이 더 없다는 것인지, 못 찾았다는 것인지), 고친 뒤 현상이 사라졌는가
  - 답이 말한 확인과 결과가 실제 도구 기록에 있는가
- 스크립트는 이 판정으로 다음 질문을 정합니다. 근거가 없는 답은 한 번 되묻습니다.
- 한도: 질문 하나에 상태와 질문을 합쳐 32k 토큰까지입니다. 스크립트가 도구 기록을 2만 4천 자 안쪽으로 줄여 보내고, 전체 기록은 따로 남깁니다.
- 키: [TypeSafe](https://docs.typesafe.ai/introduction/quickstart)에 가입해 API 키를 받아 `TYPESAFE_API_KEY`에 넣습니다. 모델은 기본값 `jev-latest`를 씁니다. 판을 고정하려면 `JEV_MODEL=jev-1.14.0`처럼 넣으세요([모델 목록](https://docs.typesafe.ai/models)).
- 다른 판정 모델로 바꾸려면 `walk.py`의 `jev()`를 그 모델의 호출로 바꿉니다. 돌려주는 형식은 `{질문 이름: 고른 보기 또는 0~1 확률}`으로 같게 맞춥니다. 정해 둔 보기 가운데 하나를 구조화된 출력으로 안정되게 내는 모델이어야 합니다. 조사 에이전트와 같은 모델은 피하세요. 자기 답을 채점하게 됩니다.

### 3. 설정을 두는 곳

설정 파일 하나에 `이름=값`을 한 줄씩 적습니다.

- 위치: `~/.config/problem-solving/settings.env` (Windows에서는 `C:\Users\<사용자>\.config\problem-solving\settings.env`)
- 다른 위치에 두려면 환경 변수 `PROBLEM_SOLVING_SETTINGS`에 그 경로를 넣습니다.
- 같은 이름의 환경 변수가 있으면 그 값이 파일보다 먼저입니다.
- 키는 스킬 폴더 안에 두지 마세요. 스킬을 공유하거나 커밋할 때 함께 나갈 수 있습니다.

```env
# 쓰는 방식 하나만 넣어도 됩니다
INVESTIGATOR_CLAUDE_MODEL=opus
INVESTIGATOR_CODEX_MODEL=<Codex에서 쓸 모델 이름>
TYPESAFE_API_KEY=<TypeSafe에서 받은 키>
# JEV_MODEL=jev-latest
```

Python 3과 고른 CLI(`claude` 또는 `codex`)가 필요합니다. 시험은 `scripts` 폴더에서 `python -m unittest test_walk`로 돌립니다(모델과 키는 쓰지 않습니다).
