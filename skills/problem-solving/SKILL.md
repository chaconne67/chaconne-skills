# 문제해결

먼저 아래 「스크립트에 필요한 것」을 확인하고, 그다음 이 스킬 폴더의 `scripts/walk.py`를 인자 없이 실행해 출력된 안내(방식 고르기와 절차)를 따르세요. 직접 진행도 그 안내의 절차대로 합니다.

## 어떻게 작동하나

질문 순서는 현상 → 원인을 거슬러 묻는 연속 질문 → 버드뷰(목적·정상 흐름·처음 어긋나는 곳) → 해결책입니다. 방식은 두 가지입니다.

- 직접 진행: 지금 쓰는 에이전트가 이 질문들을 스스로 묻고, 질문마다 그때 새로 확인한 증거로 답합니다. 따로 갖출 것이 없습니다.
- 스크립트 진행: `walk.py`가 질문 순서를 쥐고, 지금까지의 대화를 모르는 새 조사 에이전트(Claude Code나 Codex CLI)에게 질문을 하나씩 던집니다. 판정 모델 Jev가 답마다 질문에 맞는 답인지, 답이 말한 확인이 실제 도구 기록에 있는지를 가립니다. 일을 해 온 에이전트는 원인을 미리 정해 두고 답을 거기에 맞추기 쉬워서, 묻는 쪽과 답하는 쪽과 가리는 쪽을 나눈 것입니다.

조사 중에는 원본을 바꾸지 않고, 고치는 것은 결과를 본 사용자가 승인한 뒤입니다. 왜 이런 구조인지는 [README.md](README.md)에 있습니다.

## 스크립트에 필요한 것

| 필요한 것 | 비고 |
|---|---|
| Python 3.8 이상 | 표준 라이브러리만 씀 |
| Claude Code CLI(`claude`)나 Codex CLI(`codex`) 중 하나, 로그인된 상태 | 조사 에이전트. 토큰을 많이 써서 구독 요금제 로그인을 권함 |
| `TYPESAFE_API_KEY` | Jev 키. [TypeSafe](https://docs.typesafe.ai/introduction/quickstart)에서 발급(100만 입력 토큰당 0.042달러) |
| 선택: `INVESTIGATOR_CLAUDE_MODEL`, `INVESTIGATOR_CODEX_MODEL` | 조사 모델. 없으면 그 CLI의 기본 모델. 에이전트 코딩 최상위급을 권함 |
| 선택: `JEV_MODEL` | 기본 `jev-latest` |

`walk.py`는 값을 환경 변수에서 읽고, 없으면 `~/.config/problem-solving/settings.env`(위치는 환경 변수 `PROBLEM_SOLVING_SETTINGS`로 바꿈)의 `이름=값` 줄에서 읽습니다.

이것들이 있는지는 당신이 이 컴퓨터에서 직접 확인하세요. 빠진 것이 있으면 조사를 시작하기 전에 사용자에게 무엇이 빠졌는지 알리고, 갖춰서 스크립트로 할지 지금 직접 진행으로 할지 물으세요. 갖추기로 하면 설치는 사용자 동의를 받아 당신이 하고, 로그인과 키 발급처럼 사람만 할 수 있는 일만 사용자에게 맡기세요. 키 값은 채팅으로 받지 말고 사용자가 둔 곳(쓰고 있는 `.env` 등)에서 읽어 오세요. 모델은 대신 고르지 마세요.

다른 조사 CLI나 판정 모델을 쓰려면 `walk.py`의 `claude()`·`codex()`나 `jev()`를 바꾸면 됩니다. 조사 쪽은 실제 도구 실행 기록을 `observation`으로 남겨야 하고, 판정 쪽은 `{질문 이름: 고른 보기 또는 0~1 확률}` 형식을 지키되 조사 에이전트와 같은 모델은 피하세요. 시험은 `scripts` 폴더에서 `python -m unittest test_walk`로 돌립니다(모델과 키는 쓰지 않습니다).
